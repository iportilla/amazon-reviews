Class lab · Embeddings

Classifying Amazon reviews with embeddings

Zero-shot sentiment: no labeled training data, just two sentences describing each class.

intro_to_embeddings_review_classifier.ipynb

Today's lab walks through the beginner notebook in the amazon-reviews repo. By the end, you'll have built a sentiment classifier that gets about 95% accuracy on real Amazon reviews without training anything.

Learning goals

Three ideas you'll leave with

01

Embeddings

A list of numbers that captures the meaning of a piece of text.

02

Similarity

Texts with similar meaning get similar numbers. Cosine similarity measures how close.

03

Zero-shot

Label a review by checking which class description it sits closest to.

These three map to the notebook's opening cell. Everything else in the lab builds on them.

Step 2 · Your first embedding

Text in, 1,536 numbers out

Input text

"I love this coffee!"

Embedding vector

[-0.0443, -0.0314, -0.0405, -0.0301, -0.0415, … ]

1,536 values

def embed(texts):
    response = client.embeddings.create(
        model=MODEL, input=texts)
    return [np.array(item.embedding)
        for item in response.data]

Every text, short or long, becomes the same-length vector. The numbers mean nothing alone; what matters is how they compare to other embeddings.

The helper takes a list so we can embed many texts in one API call. Point out that a one-word input and a paragraph both produce 1,536 numbers.

Step 3 · Measuring similarity

Cosine similarity: closer to 1 means closer in meaning

def similarity(a, b):
    return np.dot(a, b) / (
      np.linalg.norm(a) *
      np.linalg.norm(b))

Embeddings capture topic and tone

Same topic, same tone scores highest. Same topic, opposite tone is still close. A different topic is far away.

From the notebook's 4x4 similarity table. The negative coffee sentence is still fairly close because it's about coffee. That matters later: topic can compete with sentiment.

OpenAI embeddings have length 1, so ‖a‖ ‖b‖ = 1 and the score is just the dot product.

Cosine similarity ignores how long the vectors are and only measures the angle between them. Numerator: the dot product, multiply matching coordinates and add them up (1,536 terms for our embeddings). Denominator: the two lengths, which normalize the result to the range -1 to 1. The diagram uses the notebook's scores: 0.65 means an angle of about 49 degrees (arccos 0.65), 0.26 about 75 degrees. In practice, text embeddings rarely go negative; unrelated text sits around 0.1 to 0.3, which is why the stale-chips review scored only 0.298 against the negative description and still won. Because OpenAI embeddings are normalized to length 1, np.dot(a, b) gives the same answer as the full formula; the notebook's similarity() divides by the norms anyway so it works for any vectors.

Step 4 · The classification idea

Zero-shot: the closest description wins

1

Describe each class

"An Amazon review with a negative sentiment."

2

Embed them

Same model as the reviews, so the vectors are comparable.

3

Pick the closest

For each review, the most similar description is the prediction.

"Zero" because we use zero labeled examples. The class is defined only by a sentence.

This is the core trick of the lab. No training loop, no labeled data: two sentences define the two classes.

Step 6 · Classify every review

The whole classifier fits in a few lines

labels = {
  "negative": "An Amazon review with
      a negative sentiment.",
  "positive": "An Amazon review with
      a positive sentiment.",
}
label_vectors = embed(list(labels.values()))

def classify(vector):
  scores = [similarity(vector, lv)
            for lv in label_vectors]
  return list(labels)[np.argmax(scores)]

Two API calls total

Only the two descriptions are embedded. The reviews' vectors are already in the dataset.

argmax picks the winner

Score the review against each description, return the label with the highest similarity.

reviews["predicted"] =
  reviews["embedding"].apply(classify)

Walk through classify line by line. Adding a class is just adding a dictionary entry, which is exactly what exercise 2 asks for.

Positive is the focus class, the usual convention (and scikit-learn's default). Precision reads down the "predicted pos" column: 747 of 752 positive predictions were right. Recall reads across the "true pos" row: 747 of 789 positive reviews were found. Both are high because positives are 85% of the data. Swap the focus to negative and the same matrix gives TP 131, FP 42, FN 5: precision 131/173 = 75.7%, recall 131/136 = 96.3%. About 1 in 4 "negative" flags is actually a happy review. F1 = 2 × P × R / (P + R)

A harmonic mean punishes imbalance: P = 1.0 and R = 0.1 average to 0.55, but F1 is only 0.18.

Macro-F1 = average over classes

(.848 + .970) / 2 = 0.909, the README's number.

Why not just accuracy?

Always guessing "positive" scores 85% accuracy, yet catches zero complaints: macro-F1 only 0.46.

Per-class metrics from the same confusion matrix. Positive class: precision 747/752 = 0.993, recall 747/789 = 0.947, F1 = 0.970. Negative: precision 0.757, recall 0.963, F1 = 0.848. Macro-F1 = 0.909 matches the "Sentence descriptions" row in the results table. The "always positive" baseline: accuracy 789/925 = 85.3%, negative F1 = 0, positive F1 = 0.921, so macro-F1 = 0.46. That's why the README reports macro-F1 alongside accuracy on imbalanced data.

Recap

What to remember

Embedding

Turns text into a list of numbers that represents its meaning.

Cosine similarity

Tells us how close two meanings are.

Zero-shot

Compare each text with a description of each class and pick the closest. No labeled training data needed.
